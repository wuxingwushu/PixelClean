### 1.2 内部数据结构（全 private，方案 C「稠密索引数组 + 槽位链表」）

### 1.3 莫顿编码（L165-175）
```cpp
inline uint_fast32_t Morton2D(uint_fast16_t x, uint_fast16_t y)
{
    uint_fast64_t m = x | (uint_fast64_t(y) << 32);
    m = (m | (m << 8)) & 0x00FF00FF00FF00FF;
    m = (m | (m << 4)) & 0x0F0F0F0F0F0F0F0F;
    m = (m | (m << 2)) & 0x3333333333333333;
    m = (m | (m << 1)) & 0x5555555555555555;
    m = m | (m >> 31);
    m = m & 0x00000000FFFFFFFF;
    return uint_fast32_t(m);
}
```
位模式 `x0y0x1y1…`；输入上限 16 bit/轴，返回 32 位（实际有效 2×16 bit）。注释示例：`(3,5) → 21`。

**3D 类比**：`Morton3D(x,y,z)` 三路交错，掩码按 3 位一组（`…0111` 类模式）。**位预算变化**：32 位返回值只能容纳 ~10 bit/轴（10×3=30）；在 `mStorey=12`（gridDim=4096）下每轴坐标需 12 bit → 共 36 bit，**必须改用 64 位 Morton3D（21 bit/轴）**。这是纯 2D 假设，无法原样搬用。

### 1.4 层偏移（L196-202）
```cpp
inline unsigned int Excursion(int storey)
{
    int k = mStorey - storey;
    if (k <= 0) return 0;
    return (unsigned int)(((1ULL << (2 * k)) - 1) / 3);
}
```
公式 `off(storey) = (4^(mStorey-storey) - 1)/3`：根层 `storey=mStorey` 偏移 0（1 格），`mStorey-1` 偏移 1（4 格），`mStorey-2` 偏移 5（16 格）…… 层 `storey` 含 `4^(mStorey-storey)` 格。注释（L191-194）明确：旧实现为 `(4^(mStorey-storey+1)-1)/3`（每层预留 4 倍容量以兼容任意 `mGridDim`），新实现把 `mGridDim` 取整为 2 的幂后本公式即精确紧凑布局，数组长度为旧实现的 1/4。

**3D**：`k = mStorey - storey`，偏移 `(8^k - 1)/7`，层 `storey` 含 `8^(mStorey-storey)` 格，总格数 `(8^mStorey - 1)/7`。基数 4→8 是**指数级**代价（见 §6）。

### 1.5 层选择规则 `Storey(FLOAT_ R)`（L220-235）
```cpp
unsigned int r = (unsigned int)(R * 2 + 0.99);
if (r == 0) return 1;
unsigned long index;
#if defined(_MSC_VER)
_BitScanReverse(&index, r);
#else
index = 31 - __builtin_clz(r);
#endif
return (int)index + 1;
```
即 `storey = floor(log2(ceil(2R))) + 1`，保证**层 storey 的格边长 `2^storey > 2R`**（对象直径可被单格容纳）。`R=3.5 → 直径8 → index=3 → storey=4`。

**3D 规则不变**：判据是「球直径 2R 与格边长」的关系，与维数无关，公式可原样复用；变化的是**层数上限与格数**（同样 `mGridDim` 下 3D 每层格数是 2D 的 `2^(mStorey-storey)` 倍）。

### 1.6 坐标转换与格号计算 `atIndex(Vec2_ xy, FLOAT_ R)`（L260-315）
1. `xy += mExcursion;`（L263）
2. clamp 到 `[0, mGridDim-1]`（L267-271，防位运算溢出）
3. `glm::ivec2 pos = (xy);`（L273）
4. `int _storey = Storey(R);`（L276）
5. `if (_storey > mStorey) return mGridSize;`（L280-281）——比整张网格还大 → 网格外（注释：修复旧实现 `ExcursionVector[_storey]` 越界读）
6. `pos >>= _storey;`（L284）即除以 `2^_storey`
7. 格边界 `Spos = pos << _storey;` `Epos = (pos + 1) << _storey;`（L287-288）
8. 跨格判定（L291-292）：
```cpp
if ((Spos.x > (xy.x - R)) || (Epos.x < (xy.x + R)) ||
    (Spos.y > (xy.y - R)) || (Epos.y < (xy.y + R)))
{ ++_storey; pos >>= 1; if (_storey > mStorey) return mGridSize; }
```
9. 返回（L304，`CurerExcursionVector && Morton_define` 路径）：
```cpp
return ExcursionVector[_storey] + Morton2D((uint_fast16_t)pos.x, (uint_fast16_t)pos.y);
```
非莫顿回退（L306/312）：`ExcursionVector[_storey] + (pos.x * (1U << (mStorey - _storey))) + pos.y`（行主序、x 步长 `2^(mStorey-storey)`）。

**注意**：位置在网格外**不会**被判为 extrovert——clamp 后落到边界格；`GridExtrovert` 只由「尺寸超过整张网格」触发。`Get()` 则用查询范围越界标志 `Extrovert` 把 extrovert 列表并入结果。

**3D 改动**：跨格判定扩到 3 轴（z 项加 `Spos.z > (xy.z - R) || Epos.z < (xy.z + R)`）；`pos >>= _storey` 与 `pos << _storey` 语义不变（每层每轴减半）；`pos >>= 1` 升级不变。

**`GetDividedVision(atocr)`（L704-755）**：`atocr_pos = PFGetPos() + mExcursion` → clamp → `_storey = Storey(R)`，`if (_storey > mStorey) _storey = mStorey;`（超大对象取根层视野，L721-722）→ `pos >>= _storey`；`Spos = pos << _storey; Epos = (pos+1) << _storey;`；跨格则 `++_storey; pos >>= 1;` 并重算（L730-737）；推入自身格（`Vision.push_back(Vec2_(Spos) - mExcursion); …Epos…`）；再：
```cpp
for (int i = _storey; i <= mStorey; ++i) {
    ++_storey; pos >>= 1;
    Spos = pos << _storey; Epos = (pos + 1) << _storey;
    Vision.push_back(Vec2_(Spos) - mExcursion);
    Vision.push_back(Vec2_(Epos) - mExcursion);
}
```
**实现细节**：循环体内 `++_storey` 与循环变量 `i` 同步自增（两者恒相等），故实际推入的层级是 `s+1 … mStorey+1`——**比根层还多推一级**，该层 `pos` 全为 0、`Epos = 1<<(mStorey+1) = 2*mGridDim`，即返回一个约 2 倍网格大小的保守包围盒。用于碰撞候选收集时只是多收集对象，属保守而非错误，但迁移时应明确是否保留。返回 `std::vector<Vec2_>`，**每 2 个 `Vec2_` 构成一个矩形对角点**。

**3D**：`GetDividedVision` 的返回类型应改为「每 2 个 `Vec3_` 构成一个 AABB（min/max 角）」，层级推入逻辑扩 z；`Get` 的 2 层循环变 3 层（x/y/z），`iS >>= 1` 每层仍成立。

### 2.1 内存布局 `at()`
`BaseGrid.hpp`（`class BaseGrid SerializationInherit_`）声明：`const unsigned int width; const unsigned int height; bool NewBool = false; GridBlock *Grid;`
```cpp
virtual inline GridBlock &at(int x, int y) { return at(x * height + y); }
virtual inline GridBlock &at(glm::ivec2 pos) { return at(pos.x * height + pos.y); }
virtual inline GridBlock &at(unsigned int i) { return Grid[i]; }
```

### 2.3 `BresenhamDetection(glm::ivec2 start, glm::ivec2 end)`（L53-91）→ `CollisionInfoI`
```cpp
int dx = abs(end.x - start.x);
int dy = abs(end.y - start.y);
int sx = (start.x < end.x) ? 1 : -1;
int sy = (start.y < end.y) ? 1 : -1;
int err = dx - dy;
int e2;
const int w = width; const int h = height;
while (true) {
    if (start.x >= 0 && start.y >= 0 && start.x < w && start.y < h) {
        GridBlock& block = Grid[start.x * h + start.y];
        if (block.Collision) return {true, start, block.FrictionFactor};
    }
    if (end.x == start.x && end.y == start.y) return {false, glm::ivec2{0,0}, FLOAT_{}};
    e2 = err << 1;
    if (e2 > -dy) { err -= dy; start.x += sx; }
    if (e2 < dx) { err += dx; start.y += sy; }
}
```
整数 Bresenham，**含边界检查**（越界格跳过但继续走线）；判定用 `e2 > -dy` / `e2 < dx`（严格不等，标准变体）。返回 `CollisionInfoI{bool Collision; glm::ivec2 pos; FLOAT_ Friction;}`（`BaseStruct.hpp:101-106`）。

### 2.4 `BresenhamDetection(Vec2_ start, Vec2_ end)`（L102-178）→ `CollisionInfoD`
1. `CollisionInfoI info = BresenhamDetection(ToInt(start), ToInt(end));`（L106）
2. 边界修正：`if (info.pos.x == width) --info.pos.x;` `if (info.pos.y == height) --info.pos.y;`（L107-114）
3. 若碰撞，填 `GridPos / Friction / Collision / pos`，并算精确交点：
```cpp
FLOAT_ Difference = (end.x - start.x) / (start.y - end.y);
FLOAT_ invDifference = 1.0 / Difference;
FLOAT_ valX = start.x - end.x;
FLOAT_ valY = start.y - end.y;
```
- `calcFromX()`（L128-139）：`valX < 0` → `pos = {info.pos.x, ((end.x - info.pos.x) * invDifference) + end.y}`，`Direction = Left`；`valX > 0` → `pos = {info.pos.x + 1, ((end.x - info.pos.x - 1) * invDifference) + end.y}`，`Direction = Right`。
- `calcFromY()`（L142-153）：`valY < 0` → `pos = {(Difference * (end.y - info.pos.y)) + end.x, info.pos.y}`，`Direction = Down`；`valY > 0` → `pos = {(Difference * (end.y - info.pos.y - 1)) + end.x, info.pos.y + 1}`，`Direction = Up`。
- 决策（L156-175）：先 `calcFromX()`；若 `(valX == 0) || (pos.y < info.pos.y) || (pos.y > info.pos.y + 1)` 则 `calcFromY()`，再查 `GetCollision(info.pos.x, info.pos.y + (Down == Direction ? -1 : 1))` 为真则回退 `calcFromX()`；否则查 `GetCollision(info.pos.x + (Left == Direction ? -1 : 1), info.pos.y)` 为真则改 `calcFromY()`。

`CollisionInfoD`（`BaseStruct.hpp:111-133`）用位域 union：`bool Collision:1; unsigned char Direction:2;`（**Direction 仅 2 bit**），另有 `Vec2_ pos; glm::ivec2 GridPos; FLOAT_ Friction;`。

### 2.5 序列化（L180-219）

### 2.6 3D 替代：Amanatides-Woo 3D DDA
Bresenham 是 2D 逐格光栅化，**没有 3D 直系推广的等价简洁形式**（3D 的「Bresenham」存在多解与拓扑歧义）。标准替代是 **3D DDA（Amanatides & Woo, 1987）**：
- 输入体素坐标 `start/end`，`dir = end - start`；每轴 `step = sign(dir)`，`tDelta = 1/|dir|`，`tMax = ((step>0 ? (floor(start)+1-start) : (start-floor(start))) / |dir|)`（或体素中心约定下的距离到首个边界）。
- 循环：取 `tMax` 最小的轴 `a`，`voxel[a] += step[a]`，`tMax[a] += tDelta[a]`，测试该体素 `Collision`；当 `voxel == endVoxel` 停止。
- 每步恰好跨一个体素边界，**复杂度 O(dx+dy+dz)**，与 Bresenham 同阶；天然给出「跨过的是哪个轴的面」。
- 与 Bresenham 相同的局限：只访问射线中心穿过的体素，**角/边相接的体素会被漏掉**（需要 supercover/保守变体才不穿角）。
- 浮点版精确交点：由最后推进的轴决定面，`t_prev` 处求交；方向枚举需从 4 值扩到 **6 值**（加 Front/Back），`CollisionInfoD::Direction` 的 2 bit 位域必须扩为 3 bit，`GridPos` 改 `glm::ivec3`。现有「先 X 面、再 Y 面、再用邻格碰撞做 tie-break」的逻辑要改为「3 个候选面取最小 t，再用另外两轴的邻格做 tie-break」。

**`LightweightOutlineUnit(int x,int y)`（L164-212，严格）**

- 左下：`if (!GetCollision(x,y+1)) { if (!(GetCollision(x-1,y) && !GetCollision(x-1,y+1))) push {x,y+1} }`

**`MinOutlineUnit(int x,int y)`（L214-255，最严）**

- 左下：`if (!GetCollision(x-1,y+1)) { if (!GetCollision(x-1,y) && !GetCollision(x,y+1)) push {x,y+1} }`

三档的语义：完整版只要角邻域内**任一**为空就出角（用于凸/凹都保真、点数多）；轻量版用对角相等/邻接条件过滤掉直边内部的冗余角；最小版要求**两个轴邻 + 对角**同时为空（只保留真正的凸角）。每个角点同时写 `MaxOutlineCentreMass[OutlineSize] = MaxOutlineCentre(x,y);` 与 `FrictionSet[OutlineSize] = at(x,y).FrictionFactor;` 再 `++OutlineSize;`。

### 3.4 `MaxOutlineCentre(int x, int y)`（L264-344）：包含该格的最大贪婪矩形中心
1. 列向连续段：`y_top` 上溯 `while (y_top > 0 && GetCollision(x, y_top-1)) --y_top;`，`y_bot` 下探 `while (y_bot < (int)height-1 && GetCollision(x, y_bot+1)) ++y_bot;`（L271-276）。
2. `row_count = y_bot - y_top + 1;` 并 **`new int[row_count]` ×2**（`left_bounds`/`right_bounds`，L279-280）——**每次调用都堆分配**（而每个轮廓点都会调用一次）。
3. 逐行预计算含 x 的水平连续段：`while (l > 0 && GetCollision(l-1, r)) --l;` / `while (r_ < (int)width-1 && GetCollision(r_+1, r)) ++r_;`（L287-289）。
4. 枚举 `(top,bottom)` 求最大面积矩形（L297-335）：`top` 从 `y_top` 到 `y`；`cur_left/cur_right` 随 `bottom` 增加取交（`if (lb > cur_left) cur_left = lb; if (rb < cur_right) cur_right = rb;`）；仅当 `bottom >= y` 时更新最优；两条早停：
   - `if (cur_width * (y_bot - top + 1) <= best_area) continue;`（L305）
   - `if (cur_width * (y_bot - top + 1) <= best_area) break;`（L331）
5. `delete[] left_bounds; delete[] right_bounds;`（L337-338）
6. 返回（L340-343）：
```cpp
return Vec2_(static_cast<FLOAT_>(best_x_min + best_x_max + 1) * FLOAT_(0.5),
             static_cast<FLOAT_>(best_y_min + best_y_max + 1) * FLOAT_(0.5));
```
即最大矩形的几何中心。复杂度最坏 `O(h * (w + h))`（含逐行水平扫描），且**每调用一次两次堆分配**。

### 3.5 3D 类比与规模问题
- **3D 必须产出什么**：体素边界的**表面点/角点**。每个体素有 **8 个角**；判定邻域从 2D 的 2×2（4 格）扩为 **2×2×2 = 8 体素**（角点所邻接的 8 个体素），再按完整/轻量/最小三档给不同条件（完整版：8 个中任一为空即出角；最小版：与角点共享**三个面**的 3 个轴邻体素 + 对角体素皆空才出角）。
- **输出点结构**：`OutlineSet` 改 `Vec3_*`；`MapOutline::face` 从 4 个 2D 对角向量扩为 **8 个 `±1` 三元组**（`{-1,-1,-1} … {1,1,1}`），对应体素的 8 个角方向。
- **数组规模**：`W*H*3` → 应为 `W*H*D*8`（每体素最多 8 角）；即使沿用「3 倍」的保守习惯也必须改，否则溢出更严重。以 `W=H=D=256` 计：2D 类比是 `256*256*3 = 196,608` 项，3D 实际最坏 `256^3*8 = 134,217,728` 项（`Vec3_` 12 B → 1.6 GB），**这是内存不可行区**。现实方案：只对**表面体素**（至少一个 6 邻为空）做角点生成、用稀疏 `std::vector` 按需增长、或改为「每面片生成 4 角」的 marching-cubes 风格表面输出而非全角点枚举。
- **`MaxOutlineCentre` 的 3D 化**：从「包含该格的最大矩形」变为「包含该体素的最大空/实长方体」——需要同时维护 z 向连续段，再在每个 z 切片上做 2D 最大矩形（直方图法），复杂度从 `O(h*(w+h))` 升到至少 `O(d * h * w)` 量级；且**每点两次堆分配的开销在 3D 下会被放大数倍**，必须改为复用缓冲区。
- **扫描成本**：`UpdateOutline` 的 `O(W*H)` 三重变 `O(W*H*D)`，且完整版会对每个碰撞体素调用 `MaxOutlineCentre` → 3D 下极易成为瓶颈。

### 4.10 3D 类比
- 新增 `mNumberZ / mOriginZ / mPosZ`；`MovePlateInfo` 加 `int Z`。
- 数组布局：`PlateAt(x,y,z) = &mPlate[x*NumberY*NumberZ + y*NumberZ + z]`；`LPlate` 尺寸 `max(NumberX, NumberY, NumberZ)`。
- `UpData` 三轴版本：`fabs(X) < NumberX && fabs(Y) < NumberY && fabs(Z) < NumberZ`；**滚动顺序**需定 3 轴顺序（如 Z→Y→X），且跳过逻辑从「1 个一维区间」升级为「2 个已重建的**面**」——二维里 `MovePlateY` 只需跳过 `tX..NumberX+wX` 一段列，三维里 Z 滚动需跳过 X/Y 两个方向已重建的**整片**区域（或接受重复 delete+generate，代价是回调调用量翻倍）。这是 3D 迁移中最容易出错的一处。
- `ALLUpData` 三重循环；`GetCalculatePosX/Y/Z`、`ExcursionGetPlate(x,y,z)`、`CalculateGetPlate` 三个重载加 z。
- 贪心方块分配（`MapDynamic.cpp:41-106`）从 2D 方形 `i×i` 升级为 3D 立方 `i×i×i`，`Morton2D` → `Morton3D`，并需 3 层占用检测（原代码只检测 `fy` 行与 `fx` 列）。

## 6. 内存布局与性能要点

1. **`PixelBlockEdgeSize = 16`（`BaseDefine.h:6`）是 2 的幂**，配套 `PixelBlockPowerMaxNum = 4`（L7）与 `PixelBlockPowerMinNum = 0xF`（L8）。`MapDynamic::at` 用 `x >> 4` 取板块、`x & 0xF` 取板块内偏移——**位运算替代除法/取模**。每板块 `16×16 = 256` 个 `GridBlock`；3D 每 chunk `16×16×16 = 4096` 个，**内存 ×16**。`MapDynamic.cpp:99-100` 的两条 `assert` 明确要求该常量为 2 的幂。
2. **`BaseGrid::at` 布局**：`x*height + y`（x 步长 = height，y 步长 = 1）→ 3D `x*height*depth + y*depth + z`（x 步长 = `height*depth`，y 步长 = `depth`）。
3. **`MovePlate::PlateAt` 布局**：`x*mNumberY + y` → 3D `x*NumberY*NumberZ + y*NumberZ + z`。
4. **`GridSearch` 索引区**：`mCellHead` 4 B/格，总格数 2D `(4^mStorey-1)/3`。`SetMapRange(1024)` → `Size=4096`、`mGridDim=4096`、`mStorey=12`、`mGridSize=5,592,405` → `5,592,405 × 4 B = 21.3 MiB`（注释 L423 写「≈21.4 MB」，旧 `vector<vector<*>>` 实现约 537 MB）。
   **3D 灾难性放大**：同样 `mGridDim=4096`（`mStorey=12`）时格数 `(8^12-1)/7 = 9,817,068,105` → `×4 B ≈ 39.3 GB`。要在 3D 下维持与 2D 相当的索引内存（~5.6 M 格 / ~9.6 MB），只能取 `mStorey=8`（`(8^8-1)/7 = 2,396,745` 格 ≈ 9.6 MB）→ **`mGridDim = 256`**，即 3D 世界每轴分辨率必须从 4096 降到 256。这是本次迁移最硬的约束。
5. **`Morton2D` 位宽**：返回 32 位 → 每轴 ≤16 bit。3D 下 32 位只够 ~10 bit/轴（`mStorey ≤ 10`）；`mStorey=12` 需 36 bit → **必须用 64 位 Morton3D**。`atIndex` 里 `(uint_fast16_t)pos.x` 的窄化转换在 3D 下也必须改为 64 位路径。
6. **`GridSearch::UpData` 的复杂度**：O(对象数) 整树重建；只清 `mDirtyCells`（成本 ∝ 对象数而非格数），稳态零堆分配；多线程路径 `UpDaraWorkeTask` 并行算 `mNewIndex`（写不相交区间）+ 主线程 `UpDaraWorkeTaskEnd` 串行 `ApplyRebuild`。3D 下 `atIndex` 的 clamp/移位/Morton 成本不变，但 `Get()` 的**遍历格数从 O(k²) 变 O(k³)**（k = 查询跨度），是查询侧的主要放大点。
7. **`BaseOutline` 内存**：`W*H*3` 项 ×（`Vec2_` 8 B + `Vec2_` 8 B + `FLOAT_` 4 B）≈ 60 B/项；`256×256` 网格 ≈ 11.8 MB。3D 最坏 `W*H*D*8` 项 → `256³×8 ≈ 1.34e8` 项 × 28 B ≈ 3.8 GB（其中 `MaxOutlineCentreMass` 与 `OutlineSet` 各 12 B、`FrictionSet` 4 B），**不可接受**，必须改为稀疏/表面体素驱动。
8. **`MaxOutlineCentre` 的隐藏开销**：每个轮廓点调用一次，每次 `new int[row_count]` ×2 + `delete[]` ×2（L279-280, 337-338）。一个中等形状可能产生上万轮廓点 → 上万次堆分配/释放。3D 版本必须改为复用缓冲区。
9. **`MapDynamic` 的构造开销**：贪心方块搜索 `for e<wh` × 行/列检测，最坏 O(W·H·min(W,H)·min(W,H))；3D 需检测 3 个面，且 `BaseGridBuffer` 以 `new char[] + placement new` 手工管理（`GridBuffer` 连续 `W·H·16²` 个 `GridBlock`；3D 为 `W·H·D·16³`，即板块数不变时内存 ×16）。
10. **内存管理不匹配（迁移时应一并修正）**：`MovePlate::~MovePlate` 的 `delete (char*)mPlate/LPlate`（L124-125）、`MapDynamic::~MapDynamic` 的 `delete (char*)BaseGridBuffer; delete GridBuffer;`（L118-119）、`MapDynamic` 构造的 `delete DataBool;`（L107）——均为 `new[]` 配 `delete`。
11. **`GridSearch` 的 `Remove` 复杂度**：O(该格对象数) 链内查找（`mGridIndex` 过期时回退到 `GridExtrovert` 线性查找）。

## 7. 迁移风险/待确认清单

- `BaseOutline` 的 `MaxOutlineCentreMass` 在 JSON 反序列化构造路径未分配（`BaseOutline.hpp`），且 `W*H*3` 容量小于完整版最坏 `4*W*H` → **越界写风险**；3D 下最坏为 `8*W*H*D`。
- `GetDividedVision` 的循环实际推入到 `mStorey+1` 层，返回约 2 倍网格大小的保守 AABB；3D 迁移需决定保留还是修正。
- `MapStatic::FMBresenhamDetection` 与 `MapDynamic::FMBresenhamDetection` 是**两套不同的 Bresenham 判据**（`e2 > -dy / e2 < dx` vs `e2 >= dy / e2 <= dx`），浮点版还有 L212 `++infoI.pos.x` 的差异；3D DDA 统一时应明确以哪一套的 45° 行为为准。
- `GridSearch::atIndex` 对网格外位置只做 clamp，不判 extrovert（extrovert 仅由「尺寸超过整张网格」触发）——3D 下世界坐标范围更大，这一语义是否仍合适需确认。
- `CollisionInfoD::Direction` 目前 2 bit 位域，3D 需 3 bit；`CheckDirection` 枚举与所有 `switch/比较` 点需同步。
- `MovePlate` 的 3D 滚动跳过逻辑（原 2D 只跳 1 个一维区间）是回调正确性的关键，3D 需重新设计。
- `PhysicsFormwork::PFGetPos()` 返回 `Vec2_`、`PFGetCollisionR()` 返回标量半径、`PFGetAngle()/PFSetAngle()` 为 2D 单角；`GridSearch` 依赖这些接口，3D 需同步升级为 `Vec3_` 与（可能的）姿态四元数——本次仅确认接口形态，未展开其余物理类。
