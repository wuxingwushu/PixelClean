# PhysicsLiquid 液体模拟（PBF）冗余分析报告

> 分析对象：`PhysicsBlock/PhysicsLiquid.hpp` / `PhysicsLiquid.cpp`（Position Based Fluids，移植自 Floaty-main）
> 分析方法：逐函数通读 + 关联模块（PhysicsWorld / PhysicsAngle / PhysicsShape / BaseCalculate / PhysicsParticle）交叉核对字段读写
> 文档内容：① 算法与数据流概览 ② 已实现优化盘点（防止误报）③ 冗余问题详单（按严重性分级，含位置/成因/量化/修复建议）④ 容易误判的"伪冗余" ⑤ 典型场景量化估算 ⑥ 修复优先级路线
>
> 结论速览：**最重的三项冗余都在"每帧重复重建本可缓存的数据"**——① 刚体采样点布局每帧全量重建（R1）；② 静态刚体的"密度采样点 + 几何钳制"双重边界机制使 N 膨胀（R2）；③ 边界探测对全量粒子每子步无预筛重复执行（R3）。其余为每对/每子步级的重复计算与死存储，量级递减。

## 一、算法与数据流概览

### 1.1 Update 主流程（`PhysicsLiquid.cpp L1114-L1149`）

```
Update(time)
 ├─ param.Sanitize()                        （每帧参数清洗）
 ├─ BuildSolidSamples()                      （刚体布采样点 → mSamples/mSolids/mSolidXf，每帧清空重建）
 ├─ SyncPositions()                          （组合快照：流体[0,n) + 采样点[n,N)）
 ├─ FindNeighbors(1.3h)                      （哈希链表邻居搜索，每帧一次）
 ├─ MarkInside()                             （动态刚体内部标记，每帧一次）
 ├─ for s in 0..substeps(=6)
 │   ├─ IntegrateFluid(dt)                   （半隐式欧拉）
 │   ├─ SolveFluidJacobi()                   （λ 遍 + Δp 遍，配对缓存 mPairDir/mPairW）
 │   ├─ ApplyDeltas() → ProjectSolids()      （pos += Δp + 刚体最小二乘拟合）
 │   ├─ SolveMapBoundaries()                 （地形+静态+动态刚体几何钳制，8 向搜索+二分贴面）
 │   └─ EnforceCFL(dt)                       （位移钳制 + v = Δx/dt）
 ├─ ApplyXSPH()                              （帧级黏性，每 Update 一次）
 └─ CommitSolids(time) / CommitFluid()       （速度/位置回代）
```

### 1.2 工作数组清单（`PhysicsLiquid.hpp L245-L267`）

| 数组 | 尺寸 | 写入者 | 读取者 | 备注 |
|---|---|---|---|---|
| `mPos` | N | Sync/Integrate/ApplyDeltas/Boundaries | 全阶段 | 主工作区 |
| `mVel` | **N** | SyncPositions、IntegrateFluid、EnforceCFL、XSPH（均只写 [0,n)） | 同左（只读 [0,n)） | **采样点段为死槽位（R10）** |
| `mPrevPos` | **N** | SyncPositions、IntegrateFluid（均只写 [0,n)） | EnforceCFL（只读 [0,n)） | **采样点段死槽位 + 死存储（R10/R11）** |
| `mGrad` | **N** | λ 遍写**全部 N** | Δp 遍表面张力分支（只读流体对） | **采样点段写了从不读（R10）** |
| `mDelta` | N | Δp 遍写全部 | ApplyDeltas、ProjectSolids（含采样点） | 正常 |
| `mLambda` | N | λ 遍写全部 | Δp 遍（j 可为采样点） | 正常 |
| `mBoundaryDisp` | n | Boundaries | EnforceCFL | 正常 |
| `mInside` | n | MarkInside | λ/Δp/XSPH | 正常（帧内陈旧，见 R14） |

| `mPairDir`/`mPairW` | N×64 上界 | λ 遍 | Δp 遍 | 配对缓存（已优化项） |

其中 `n = mFluidCount`（流体粒子数），`N = n + mSamples.size()`（含刚体采样点）。

## 三、冗余问题详单

### 3.1 结构级冗余（高影响）

#### R1 · 刚体采样点布局每帧全量重建（静态体 100% 重复劳动）

**位置**：`BuildSolidSamples()` cpp L332-476；`RefreshSolidXform()` L306-330；`SyncSamplePositions()` L478-495（经 `SyncPositions` L517 每帧调用）。

**现象**：每次 `Update`（L1125）把 `mSamples / mSampleWeight / mSolids / mSolidXf` 全部 `clear()` 后从零重建：

- **shape**（L408-427）：逐实体格 × `per²` 细分（默认 spacing=0.24 时 `per=4`，即 **16 个采样点/格**），每点一次局部坐标计算 + push；
- **circle**（L434-444）：逐同心环、逐点 `cos/sin`；
- **line**（L451-457）：逐段细分；
- `RefreshSolidXform` 再逐刚体重建一遍变换缓存；
- `SyncSamplePositions` 再对**全部**采样点做一次 `body->pos + vec2angle(local, cs)` 世界锚定——**静态体（invMass=0，pos/angle 永不变）每帧重算出逐位相同的结果**。

**为何冗余**：采样点的**局部锚点 `local` 只取决于刚体几何**（网格图案/半径/线长），几何不随帧变化；世界锚点 = 位姿变换，静态体位姿永不变化。即静态体的整条"清空→逐格细分→重建 xf→重锚定"流水线每帧产出与上一帧完全相同的数据。

**量化**：一面 40×3 格的静态墙 = 120 格 × 16 = **1920 个采样点/帧**的重建 + 1920 次重锚定旋转乘加 + 对应 `SolidXf` 重建。几个静态构件即可让采样点数逼近甚至超过流体粒子数。

**修复建议**：
- 按 `body` 指针缓存采样布局（`local` 数组 + 计数），仅在三处失效钩子下重建：世界 Add/RemoveObject、shape 图案变更（如切割）、circle/line 半径变更；
- 静态体跳过 `SyncSamplePositions` 重锚定（世界锚点缓存直接复用）；
- `mSolidXf` 改为按需刷新（位姿未变的刚体跳过）。

**风险与权衡**：现行"每帧重建"换来的是**免失效管理的正确性**（被销毁的刚体自然从世界容器消失，不会留下悬垂采样点）。缓存方案必须在 `PhysicsWorld::RemoveObject` 挂失效通知（类似现有 `NotifyParticleRemoved` 机制），否则产生悬垂指针。建议连同失效钩子一起实现，不要只缓存一半。

#### R2 · 静态边界双重机制 + 地形不对称：N 膨胀放大全套求解成本

**位置**：采样点收集 L390-473（`PFGetMass() > 0` 的刚体全部入样，静态体 `w=0` L470）；几何钳制 `SolveMapBoundaries` L821-836（`PointSolid` 遍历 `mSolidXf` **含静态体**）；地形仅走 `FMGetCollide`（L823-825）。

**现象**：同一种物理角色（"静态墙"）存在**两套并行机制**：

| 静态几何类型 | 密度采样点（压力边界） | 几何钳制（穿透修正） |
|---|---|---|
| 地形 `MapFormwork` | ✗ 无 | ✓ 有 |
| 静态刚体（invMass=0） | ✓ 有（w=0，进邻居系统） | ✓ 有 |

静态刚体同时占用两套防线：其采样点进入 `mPos`（N = n + 采样点数），**直接放大 `FindNeighbors`（O(N)）、λ 遍（O(N)）、Δp 遍（O(N)）、`ApplyDeltas`（O(N)）的全部规模**；而贴面钳制又把采样点辛苦建立的"未穿透"重新几何投影一遍。地形已实证"仅几何钳制"即可稳定挡水（bVel 规则消法向速度，cpp L987-992 注释），静态刚体那套 w=0 采样点的边际收益只剩"接触更软"（密度场提前减速），代价却是 N 膨胀。

**为何冗余**：挡水这一职责被实现两次，其中一次（采样点）的载体规模随静态构件面积线性增长，且这些采样点**永不移动**（w=0），对它们算出的 λ、Δp 也全部丢弃（`ProjectSolids` 对 invMass=0 直接 continue，L940-943）——即静态采样点的 λ 求解是**纯投入零回报**的路径（它们唯一作用是把邻居密度抬高，间接压流体）。

**量化**：见第五节场景——静态墙采样点 ≈ 3840 个，使 N 从 10000 膨胀到 13968（+40%），λ/Δp/邻居搜索全量随之 +40%。

**修复建议**（二选一，推荐 A）：
- **A. 静态刚体退出采样**，统一走地形同款几何钳制（`PointSolid` 保留静态体即可，改动仅是 BuildSolidSamples 过滤 `invMass==0`）。收益：N 回落至纯流体规模，静态墙零采样开销；风险：贴墙手感略"硬"（无密度场预减速），与地形行为对齐；
- B. 若要保留软接触，则反向补齐对称性（地形也生成虚拟采样点）——不推荐，成本更高。

**附带发现（一致性问题）**：入样过滤条件是 `PFGetMass() <= 0 → skip`（L392），即 **mass==0 且 invMass==0 的刚体对液体完全隐形**（既无采样点也不进 `mSolidXf`，`PointSolid` 探不到，水会直接穿过去）。而头文件文档声明"静态刚体（invMass=0）采样点 w=0：只提供密度边界"（hpp L32-33）——实现与文档的"静态"判定不一致（一个看 mass>0，一个看 invMass==0）。建议统一为 `invMass==0 && mass>0` 或显式断言，避免用户构造 mass=0 的"幽灵静态体"。

#### R3 · 边界探测无帧级"近边界"预筛：深水粒子每子步全套 PointSolid

**位置**：`SolveMapBoundaries` 主循环 L877-884：每子步对**全部** n 个粒子先做 `PointSolid(p)`；`PointSolid` = `map->FMGetCollide`（哈希/网格查询）+ 线性遍历**全部** `mSolidXf` 逐个 AABB 测试（L821-836）。

**现象**：`SolveMapBoundaries` 在子步循环内执行（L1138），即每帧 6 次 × 全量粒子。对一个 90% 粒子在开阔水域的池子，每子步 ~90% 的 `PointSolid` 探测**注定为 false**（粒子既不在地形实体格、也不在任何刚体 AABB 内），但仍支付完整代价：1 次地图查询 + |mSolidXf| 次 AABB 判断。

**为何冗余**：帧内位移有严格上界——粒子每子步总位移 ≤ 0.9·cfl·h（EnforceCFL），刚体子步位移同受钳制（ProjectSolids L963-965），全帧累计漂移 ≤ 6 × 0.9·cfl·h ≈ **0.29**（默认参数）。因此"帧初离一切固体表面 > 0.29 + maxSteps·step ≈ 1.6 的粒子，整个帧内不可能触边"——这个判定每帧只需做**一次**，现在却每子步对每粒子重复做。

**修复建议**：每帧在 `FindNeighbors` 后构建一次"近边界候选集"（流体包围盒外扩 1.6 + 各刚体 AABB/地图实体格求交），子步内只对候选粒子跑 `PointSolid` 与逃逸机制。深水粒子 6 次子步全部免探测。

**量化**：n=10000、|mSolidXf|=4（两墙一板经 NearFluid 剪枝）时：现状 6×10000 = 60000 次 `FMGetCollide` + 24 万次 AABB 判断/帧；预筛后（~8% 触边）约 4800 次探测，**省 ~92%**。若未来场景刚体多、`mSolidXf` 达数十个，此条收益进一步放大（PointSolid 内部虽然每刚体 4 个比较就退出，但乘数是 6·n·|solids|）。

#### R4 · 动态刚体的三重防线叠置（机制性冗余，复盘项）

**位置**：`MarkInside` L611-629（机制一：困水跳过压力）；采样点密度推挤（机制二：w=1/m_采样 参与 Δp）；`PointSolid` 几何挤出动态刚体（机制三，L827-834，注释明确标注是修复"幽灵穿透"的追加层）。

**现象**：同一种相互作用（水 vs 动态刚体）由三层机制同时处理，其中第三层是移植 Floaty 之后追加的修复（Floaty 原版只有前两层 + 其空心软体假设）。

**定性**：这不是可简单删除的冗余——注释给出了各层的存在理由（inside 防悬浮、挤出防坠穿浮板）。但从"冗余"角度必须指出：**机制一的判定成本与机制三完全重叠**（都是"粒子是否在动态刚体内"的包含测试，`SolidContains` 同一函数），每帧至少做两遍（MarkInside 一遍、PointSolid 每子步一遍）；且挤出机制落地后，inside 标记所处理的"困水"场景存在时间被压缩到最多一个子步，其收益/成本比显著下降。

**建议**：保留三层但复盘两点：① `MarkInside` 结果可被挤出阶段复用（帧初已确认 inside 的粒子直接进 R3 的候选集）；② 用调试统计验证"挤出启用后 inside 标记的实际触发率"，若趋零可考虑将 inside 降级为仅 XSPH 使用（λ/Δp 一致放行，靠挤出兜底），简化 λ 遍的 `mInside` 分支。

### 3.2 循环级冗余（中等影响）

#### R5 · 压力梯度系数在 λ 遍与 Δp 遍重复展开

**位置**：λ 遍 L737 `gscale = (spikyScale * w * w * -3) * restInv`；Δp 遍 L786 `(spikyScale * w * w * -FLOAT_(3)) * restInv * (λi+λj)`。

**现象**：同一子步、同一对（k 相同 ⇒ `w = mPairW[k]` 相同、常量相同），这一系数被逐对计算**两遍**。配对缓存已存了方向 `mPairDir` 与核距 `mPairW`，唯独漏了这个标量系数。

**冗余量**：每有效对每子步 ~2-3 次乘法 + 1 次 load。以 26 万对 × 6 子步计 ≈ **400 万次冗余乘加/帧**。

**修复建议**：λ 遍顺手缓存 `mPairG[k] = gscale`（新增一条 FLOAT_ 平行数组，或与 `mPairW` 打包为 8 字节结构以不增内存行宽）；Δp 遍直接读。曲率项需要 `w³`，保留 `mPairW` 即可（w*w*w 现场算，1 次乘法）。

---

#### R6 · `mPairW` 哨兵双重写：每有效对每子步多一次 store

**位置**：λ 遍 L709-711：`mPairW[k] = -FLOAT_(1)` **无条件先写**，随后有效对在 L735 覆盖为真值。

**现象**：两遍式设计要求每个槽位在本子步内确定有效/无效（因为位置变了、配对有效性逐子步变化），哨兵本身是必要的；但"先写哨兵再覆盖"使**每个有效对**都产生一次注定被覆盖的 store。

**冗余量**：有效对数 × 子步数。10k 粒子 × ~19 有效邻居 × 6 子步 ≈ **110 万次冗余 store/帧**（对一级缓存压力不可忽略，写组合缓冲会合并部分，但仍占发射端口）。

**修复建议**：把哨兵写移进各失效分支（`j<0` / 采样对 / inside / `r2` 越界的 `continue` 路径各写一次 `-1`），有效路径只写一次。逻辑等价，纯粹减少一半槽位写。

---

#### R7 · 子步级循环不变量每子步重算 + Sanitize 每帧执行

**位置**：`SolveFluidJacobi` 入口 L682-690：`h, h2, poly6Scale, spikyScale, restInv, selfRho` 每次调用（每子步）重算，其中含 2 次除法与 1 组幂运算；`Update` L1121 `param.Sanitize()` 每帧 10 余个分支。

**为何冗余**：`h` 与 `ρ0` 在整个 `Update` 内不变（Sanitize 已在循环前收敛参数）。

**冗余量**：微（每子步 ~20 flops，每帧 ~120 flops）。

**修复建议**：在 `Update` 顶部算一次存入局部结构传下去，或做成按 `param` 版本号失效的成员缓存。**优先级低**，属顺手项。

---

#### R8 · `ParallelRange` 每次调用的分配开销

**位置**：cpp L651-675。每次调用构造 `std::function`（捕获 lambda，通常堆分配）+ `std::vector<std::future>`（堆分配）+ enqueue。每子步 2 次（λ/Δp）→ 每帧 12 次。

**为何冗余**：分配的是**每帧内容几乎相同的闭包与 future 容器**，属高频重复分配。

**修复建议**：① 模板化 `ParallelRange`（`template<class F>` 传引用）消除 `std::function` 堆分配；② future 向量提为成员复用（clear 保容量）。注意现有 `count < 1024` 串行快路径（L654）已规避小场景的分配——这条只影响大场景。

---

#### R9 · `FindNeighbors` 两遍重复坐标换算与自身格哈希

**位置**：第一遍 L557-569 对每粒子算 `floor(x·inv), floor(y·inv), HashCell(gx,gy)`；第二遍 L574-578 对**同一批粒子**再算一遍同样的 `floor×2`，且 3×3 邻域的中心格 `HashCell(gx,gy)` 与第一遍算出的完全同值。

**冗余量**：每帧 2N 次冗余 `floor` + N 次冗余哈希（N=14k 时 ~4.2 万次冗余换算/帧）。

**修复建议**：第一遍把 `gx/gy`（或直接 `hash(own cell)`）存进两条 int 平行数组，第二遍直接取。微到中等，实现极简单。

### 3.3 存储级冗余（低影响，但零成本可清）

#### R10 · `mVel / mPrevPos / mGrad` 的采样点死槽位；`mGrad` 采样点每子步死写

**位置**：`SyncPositions` L502-504 将 `mVel/mPrevPos/mGrad` 一律 `resize(N)`（含采样点段）；λ 遍 L754 `mGrad[i] = -gradSum` 对**全部 N** 写；而读取端——`IntegrateFluid/EnforceCFL/ApplyXSPH` 只循环 [0,n)，Δp 遍读 `mGrad` 仅在表面张力分支（限定流体↔流体对，L788-794）。

**结论**：
- `mVel`、`mPrevPos` 的采样点段：**从不读也从不写**，纯死内存（各 16B × 采样点数）；
- `mGrad` 的采样点段：**每子步被写入却从不被读**——3840 个静态采样点 × 6 子步 ≈ **2.3 万次/帧的死写** + 死内存。

**修复建议**：`mVel/mPrevPos` 按 `n` 分配（与 `mBoundaryDisp/mInside` 同策略）；`mGrad` 按 `n` 分配并把 L754 的写移进 `if (i < n)` 守卫（`mDensity` 的写已有此守卫 L755-758，照抄即可）。注意 `mDelta/mLambda` 必须保持 N（采样点真的参与），**不要**一并误删。

#### R11 · `SyncPositions` 中 `mPrevPos[i]` 的死存储

**位置**：L515 `mPrevPos[i] = p->pos;`。其后的首次读取在 `EnforceCFL`（L1001），而此前 `IntegrateFluid`（L645）已无条件覆盖 `mPrevPos[i] = mPos[i]`。Sanitize 保证 `substeps ≥ 1`，该初值**必然**被覆盖。

**冗余量**：n 次 Vec2 写/帧。删除该行即可（`mPrevPos` 本身保留，R10 只是把尺寸降到 n）。

#### R12 · 邻居三数组按 N×64 上界常驻（内存 2~3 倍冗余 + 永久死区）

**位置**：L546-551：`mNeighbors/mPairDir/mPairW` 以 `N × kMaxNeighbors(64)` 为容量上界分配；而实际写入采用 `accum` 紧排（典型 2D 邻居数 ≈ 19~25，见第五节），`[accum, N×64)` 区间为**跨帧永久死区**（存着历史残值，从不读）。

**冗余量**：三数组合计 16B/槽。N=14k 时上界预留 ≈ **14.3 MB**，实际使用 ≈ 4.2 MB，**~10 MB 死内存**；小场景（N=1k）也有 ~1 MB。

**修复建议**（任选其一）：
- 保守：容量改为"上一帧 accum × 1.5"的自适应增长（两遍法第二遍前已知上帧用量，越界再 fallback 扩容重跑）；
- 激进：两遍精确计数（先数邻居数再填表），零冗余但多一遍哈希遍历。
- 若内存不紧张也可**接受现状**——此项只占内存不耗算力，优先级由内存预算决定。

#### R13 · 圆盘采样溢出时外环空转三角函数

**位置**：L434-444。采样点达到 `kMaxSolidSamples` 后：中心点 push 返回值被忽略；每个环的内层 `break` 只跳出 k 循环，**外层 ring 循环继续运行**——每环仍计算 `cnt` 并对 k=0 算一次 `cos/sin` 再失败 break，直到 `ring > radius`。

**冗余量**：仅溢出边界情形（4096 上限打满）触发，每剩余环 ~2 次三角函数 + 若干乘法。

**修复建议**：溢出时置 flag 直接跳出双重循环（与 shape 分支的 `overflow` 处理对齐 L410-427——shape 分支已正确做了，circle 分支漏了）。

### 3.4 机制性观察（非严格冗余，一并汇报）

#### R14 · `MarkInside` 与 `PointSolid` 的包含判定重复；inside 标记帧内陈旧

- 包含判定重复已并入 R4，此处补充第二点：`MarkInside` 用**帧初位置**打标记（L1128，在子步循环之前），随后 6 个子步里粒子最多漂移 ~0.29——帧中段新进入刚体的粒子**不带标记**（靠挤出兜底），帧初在体内、中途被挤出的粒子**带着过期标记**继续跳过压力直到下帧。这是 Floaty 的同构移植行为，属算法层取舍而非 bug；若追求帧中段一致性，可把 MarkInside 挪进子步循环（代价：每子步一次全量包含判定，与 R3 的预筛合并做才划算）。

#### R15 · `AddGrid` 的参数副作用（每次调用重置全局参数组）

**位置**：L162-166。每次 `AddGrid` 按 `spacing` 反推 `particleRadius` 并调 `SyncFromParticleRadius()`——后者会**重写 eps/cohesion/curvature**（L93-95）。用户先加水、再加一块不同间距的水、再调过参数，参数组会被静默回滚。这是 API 设计层面的重复/副作用问题：生成几何的操作不应携带参数重置。建议 `AddGrid` 只在参数未初始化时 Sync，或提供显式 `syncParams` 形参。

## 四、容易误判的"伪冗余"（看似重复，实为必要）

| 疑似冗余 | 为什么不是冗余 |
|---|---|
| λ 遍重算 `dx/dy/r2`，`FindNeighbors` 不是算过一遍距离吗？ | 邻居表每帧只建一次，而子步内位置已变（积分/Δp/钳制都动过位置）；λ 遍必须用**当前**位置重算。真正的复用发生在 λ→Δp（配对缓存），已经做了 |
| 邻居半径取 1.3h > 核半径 h，λ 遍还要 `r2 >= h2` 重测一遍？ | 1.3 倍余量是为子步漂移预留的（帧建表用一整帧），越界对的过滤是必要计算而非重复 |
| `EnforceCFL` 里 a、b、d 算了三次长度 | 三者语义不同：a 是钳制基准、b 是速度分离基准、d 是最终钳制对象，数学上不可合并（bVel 规则正是靠 a/b 分离实现的） |
| `ApplyXSPH` 不复用 `mPairW` 缓存，逐对重算 poly6 | XSPH 在**最后一子步的 EnforceCFL 之后**执行，位置又被改过，spiky 系缓存必失效；且它需要的是 poly6 权重，与缓存内容不同型 |
| 粒子上的 `OldPos` 与工作区 `mPrevPos` 双记账 | 语义不同：`OldPos` 是帧级（CommitFluid 的 StaticNum 唤醒判定 L1098-1106），`mPrevPos` 是子步级（PBD 积分基准）。二者不可互相替代 |
| `kPi = 3.141592` 精度不足 | Floaty 原样常数（lib.rs `let pi = 3.141592`），核函数归一化误差 <1e-6，且与参考实现逐位对齐是移植的验收标准 |
| `mInside` 每帧 `assign(n,0)` | 必要的复位（epoch 思想不适用于逐粒子标志） |
| `CommitSolids` 用帧时间除累计位移 | 语义正确：accum 是全帧累计，除以帧时间得平均速度增量，与子步钳制口径一致 |

## 五、典型场景量化估算

**场景假设**（默认参数：r=0.15、h=0.45、spacing=0.24、substeps=6、cfl=0.12、maxDisp/子步≈0.049、帧内漂移≤0.29）：

- 流体：10000 粒子（静息水池）
- 静态墙：两面 40×3 格 shape（120 格 × 16 采样点/格 = 3840 采样点）
- 动态浮板：8×1 格（128 采样点）
- **N = 10000 + 3968 = 13968**；2D 静息态平均有效邻居 ≈ 19/粒子，有效对 ≈ N×19 ≈ 26.5 万

| 冗余项 | 每帧冗余量（估算） | 类别 |
|---|---|---|
| R1 静态采样点重建+重锚定 | 3840 点布局重算 + 3840 次旋转乘加 + xf 重建 | 计算 |
| R2 静态采样点参与 λ/Δp（w=0 零回报路径） | N 膨胀 +40% → λ/Δp/邻居搜索全量 +40% | 计算 |
| R3 深水粒子 PointSolid 探测 | ~60000 次 FMGetCollide + 24 万次 AABB（~92% 可免） | 计算 |
| R6 哨兵双重写 | ~110 万次冗余 store | 计算/访存 |
| R5 梯度系数重算 | ~400 万次乘加 | 计算 |
| R10 mGrad 采样点死写 | ~2.3 万次 store + 190 KB 死内存（三数组） | 访存/内存 |
| R9 坐标换算重复 | ~4.2 万次 floor/hash | 计算 |
| R12 邻居表过配额 | 预留 14.3 MB vs 实用 4.2 MB（~10 MB 死区） | 内存 |
| R7+R11+R8 杂项 | 数百 flop + 12 次堆分配 + 1 万次死 store | 计算/分配 |

> 量级判断：**R2 ≈ R3 > R1 > R6 > R5 > R10 > R9 > R12(纯内存) > 其余**。R1~R3 三项彼此相关：R2 落地后 N 回落、R1 的重建量随之消失大半；R3 独立于前两项。

## 七、总结

PhysicsLiquid 的算法主体（Floaty PBF 移植）本身是紧凑的，配对缓存、变换缓存、epoch 哈希、两段式边界搜索等局部优化也已到位。当前剩余冗余集中在**三个结构性重复**上：

1. **每帧重建不变数据**（R1/R2）——静态几何的采样点布局与世界锚定帧间完全不变，却每帧全量重算，且静态采样点以 w=0 身份把 N 撑大 40% 却在求解端零回报；
2. **每子步重复探测必然为假的条件**（R3）——帧内位移有界性使得"是否近边界"一帧一判即可，现在每子步全量重判；
3. **微观层面的双重写/重复展开**（R5/R6/R7/R9）——每对每子步几条指令的浪费，乘上 26 万对 × 6 子步的规模后成为可测量项。

P0 两项（R2-A、R3）改动都在个位数行级别、风险可控，且相互独立可分步验证；R1 收益最大但依赖失效钩子，建议放在 P0 验证后实施。
