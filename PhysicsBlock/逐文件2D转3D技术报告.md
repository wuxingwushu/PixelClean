### 1.3 碰撞对的加入：`AddCollisionPair(BaseArbiter *arbiterKey)`（.cpp:174-267）

**物体↔物体分支**（`arbiterKey->mArbiterType >= PhysicsArbiterType::ArbiterSS`，:176）：

1. 查双方绑定：`Ait = mBindings.find((PhysicsFormwork*)arbiterKey->mOriginalObject1)`，`Bit = ...mOriginalObject2`；`A_bound/B_bound`（:178-182）。
2. **双方都无绑定 → 直接 return**（:184）。
3. 层级掩码：`bool layerOk = true; if (A_bound && B_bound) { layerOk = (Bit->second.Layers & Ait->second.Layers) != 0; } if (!layerOk) return;`（:187-192）。**只有双方都有绑定时才做交集检查；单方绑定一律放行。**
4. OnEnter：`Ait->second.OnEnter(Ait->first, (const PhysicsFormwork*)(arbiterKey->mOriginalObject2), arbiterKey);`（:197-199）；B 侧同样调用，但**第一个实参写成 `Ait->first`**（:204-206）。这是缺陷：若仅 B 有绑定（A 未绑定），`Ait == mBindings.end()`，对 end() 迭代器取 `->first` 属未定义行为；语义上 B 的回调也应传 `Bit->first`。

## 2. `PhysicsKinematic.cpp`（327 行）+ `PhysicsKinematic.hpp`（274 行）

### 2.1 定位
运动学物体属性管理：`IsKinematic == true` 时不受重力/碰撞冲量，位置角度由外部驱动，但仍参与碰撞检测；切回动态时恢复此前速度以避免突变（hpp:111-127）。

### 2.2 `SetIsKinematic(PhysicsFormwork*, bool)`（.cpp:13-49）

```cpp
std::lock_guard<std::mutex> lock(mMutex);
KinematicData &data = GetOrCreateData(object);
if (data.IsKinematic == kinematic) return;
if (kinematic) {
    data.SavedSpeed = object->PFSpeed();
    data.SavedAngleSpeed = object->PFAngleSpeed();
    object->PFSpeed() = Vec2_{0.0f, 0.0f};
    object->PFAngleSpeed() = 0.0f;
    data.IsKinematic = true;
} else {
    data.IsKinematic = false;
    object->PFSpeed() = data.SavedSpeed;
    object->PFAngleSpeed() = data.SavedAngleSpeed;
    data.Motion = KinematicMotion{};
}
SynchronizePhysicsStateImpl(object);
```

> **关键澄清（修正任务描述中的说法）**：**清零速度发生在这里**（:33-34 的 `PFSpeed()=Vec2_{0,0}` 与 `PFAngleSpeed()=0`），不是发生在 `SynchronizePhysicsState`。`SynchronizePhysicsState` 只改 `invMass`/`invMomentInertia`（见 2.4）。

### 2.3 `MoveTo` / `RotateTo`

`MoveTo(PhysicsFormwork *object, const Vec2_ &position, FLOAT_ duration)`（.cpp:61-88）：
- 校验 `duration <= 0` → `ArgumentOutOfRangeException("duration","Duration must be greater than 0. Received: "+...)`。
- 非运动学 → `PhysicsException("MoveTo requires the object to be kinematic. Call SetIsKinematic(object, true) first.")`。
- 记录 `data.Motion.IsMoving = true; MoveStartPos = object->PFGetPos(); MoveTargetPos = position; MoveDuration = duration; MoveElapsed = 0.0f;`

`RotateTo(PhysicsFormwork *object, FLOAT_ rotation, FLOAT_ duration)`（.cpp:90-126）：
- 同样的 duration/kinematic 校验。
- 取当前角：仅当 `objType == shape || circle || line` 时 `currentAngle = static_cast<PhysicsAngle*>(object)->angle;`，否则保持 `0.0f`（.cpp:112-119）。
- 记录 `IsRotating=true; RotateStartAngle=currentAngle; RotateTargetAngle=rotation; RotateDuration=duration; RotateElapsed=0.0f;`

`SetMoveMode` / `SetRotateMode(PhysicsFormwork*, KinematicMoveMode)`（.cpp:128/138）写 `Motion.MoveMode/RotateMode`；枚举 `KinematicMoveMode{Once, PingPong}`（hpp:9-13）。

### 2.4 `SynchronizePhysicsState` / `...Impl`（.cpp:148-210）

`SynchronizePhysicsState` 只加锁并转调 `SynchronizePhysicsStateImpl`。Impl 逻辑：

- 若 `mKinematicData` 无该对象 → return。
- `isKinematic == true`：`particle` → `invMass = 0.0f`；`shape/circle/line` → `invMass = 0.0f` **且** `invMomentInertia = 0.0f`。
- `isKinematic == false`：`particle` 且 `mass > 0` → `invMass = 1.0f/mass`；`shape/circle/line` 且 `mass>0` → `invMass = 1.0f/mass`，且 `MomentInertia > 0` → `invMomentInertia = 1.0f/MomentInertia`。

即：**该函数只负责"有效质量/惯量的开闭"，不碰速度、位置、角度。**

### 2.5 `UpdateKinematicMotion(FLOAT_ deltaTime)`（.cpp:212-288）

- `deltaTime <= 0` → 抛 `ArgumentOutOfRangeException`。
- 持锁遍历 `mKinematicData`，跳过 `object == nullptr || !data.IsKinematic`。
- **移动**：`MoveElapsed += deltaTime`；若 `>= MoveDuration`：clamp `MoveElapsed = MoveDuration`；`PingPong` → `std::swap(MoveStartPos, MoveTargetPos); MoveElapsed = 0.0f;`；否则 `IsMoving = false`。随后
  ```cpp
  FLOAT_ t = (MoveDuration > 0.0f) ? MoveElapsed / MoveDuration : 1.0f;
  t = (t > 1.0f) ? 1.0f : ((t < 0.0f) ? 0.0f : t);
  auto *pp = static_cast<PhysicsParticle *>(object);
  pp->pos.x = MoveStartPos.x + (MoveTargetPos.x - MoveStartPos.x) * t;
  pp->pos.y = MoveStartPos.y + (MoveTargetPos.y - MoveStartPos.y) * t;
  ```
  **逐分量手写 lerp，没有调用 `Lerp()`。**
- **旋转**：`RotateElapsed += deltaTime`；到点后 PingPong 交换 `RotateStartAngle/RotateTargetAngle` 并归零 elapsed，否则 `IsRotating=false`；`t` 同上钳制；`static_cast<PhysicsAngle*>(object)->angle = RotateStartAngle + (RotateTargetAngle - RotateStartAngle) * t;`（.cpp:284-285）。**纯线性角插值，不取最短弧。**

调用点：`PhysicsWorld.cpp:837` `mKinematic.UpdateKinematicMotion(time);`（在碰撞检测前，使新位置参与碰撞）。

### 2.6 `Lerp` 的定义与使用

hpp:265-268：
```cpp
static FLOAT_ Lerp(FLOAT_ a, FLOAT_ b, FLOAT_ t)
{
    return a + (b - a) * t;
}
```
标量 `Lerp`，**在本 .cpp 内无任何调用点**（插值全部内联展开）。`GetOrCreateData`（.cpp:306）、`GetData`（.cpp:316，缺省返回静态 `defaultData`）、`RemoveKinematicData`（.cpp:290）、`Clear`（.cpp:300）。

### 2.7 3D 改动

- `KinematicMotion`（hpp:20-75）：`Vec2_ MoveStartPos/MoveTargetPos` → `Vec3_`；`FLOAT_ RotateStartAngle/RotateTargetAngle` → `glm::quat RotateStart/RotateTarget`（或 `vec3` 欧拉）；`MoveElapsed/RotateElapsed/Duration` 保持标量。
- `KinematicData::SavedAngleSpeed`（hpp:99）`FLOAT_` → `glm::vec3`（角速度）或 `glm::quat`（若按姿态存储）。
- `SetIsKinematic`：`PFSpeed() = Vec2_{0,0}` → `Vec3_{0,0,0}`；`PFAngleSpeed() = 0.0f` → `glm::vec3(0)` 或单位四元数。
- `UpdateKinematicMotion` 位置插值：`pp->pos = MoveStartPos + (MoveTargetPos - MoveStartPos) * t`（分量式照搬即可）。
- **旋转插值必须换成四元数 slerp**：`angle = slerp(RotateStart, RotateTarget, t)`，并在写入后**归一化**；PingPong 时交换两端四元数即可。若保留欧拉角则需处理万向节与最短弧（可复用 `MovementUtil.hpp` 的 `LerpAngle` 思路逐轴）。
- `RotateTo` 取当前姿态：`static_cast<PhysicsAngle*>(object)->angle` → `->rotation`（`glm::quat`）。
- `SynchronizePhysicsStateImpl` 的 `invMomentInertia`（标量）→ 逆惯量张量 `mat3`（运动学置零矩阵）。
- `Lerp` 保持标量；无需为 3D 改写。

### 3.3 `ProcessTriggers(GridSearch &gridSearch)`（.cpp:129-245）——重叠检测与 Enter/Stay/Exit 状态机

结构：先声明 `DeferredTriggerEvent { TriggerCallback callback; PhysicsFormwork *targetObject; }` 与延迟队列 `deferredEvents`（:131-136）。整个检测体在一个 `std::lock_guard` 作用域内（:138-239），**回调在锁外统一触发**（:241-244），避免回调内重入死锁。

锁内流程：

```cpp
struct TriggerEvent { TriggerHandle triggerHandle; TriggerConfig *config; PhysicsFormwork *targetObject; TriggerEventType eventType; };
std::vector<TriggerEvent> events;
std::vector<PhysicsFormwork *> nearbyObjects;

for (auto &[handle, config] : mConfigs) {
    auto &activeOverlaps = mActiveOverlaps[handle];
    std::unordered_set<PhysicsFormwork *> currentOverlaps;

    Vec2_ minPos = config.TriggerBounds.Center - config.TriggerBounds.HalfSize;
    Vec2_ maxPos = config.TriggerBounds.Center + config.TriggerBounds.HalfSize;
    gridSearch.Get(minPos, maxPos, nearbyObjects);          // 空间索引粗筛

    for (auto *obj : nearbyObjects) {
        if (obj == nullptr) continue;
        if (obj->PFGetType() == PhysicsObjectEnum::particle &&
            ((PhysicsParticle *)obj)->IsLiquidParticle) continue;   // 跳过液体粒子
        if (!config.TriggerBounds.Contains(obj->PFGetPos())) continue; // 精确点包含检测
        currentOverlaps.insert(obj);
        bool wasOverlapping = (activeOverlaps.find(obj) != activeOverlaps.end());
        if (!wasOverlapping) { if (config.OnTriggerEnter) events.push_back({handle, &config, obj, TriggerEventType::Enter}); }
        if (config.OnTriggerStay) events.push_back({handle, &config, obj, TriggerEventType::Stay});
    }
    for (auto *obj : activeOverlaps) {
        if (currentOverlaps.find(obj) == currentOverlaps.end()) {
            if (config.OnTriggerExit) events.push_back({handle, &config, obj, TriggerEventType::Exit});
        }
    }
    activeOverlaps = std::move(currentOverlaps);   // 本帧状态覆盖
}
```

随后遍历 `events`，按 `eventType` 从 `event.config->OnTrigger*` 取回调（先判 `config == nullptr` 跳过），非空则压入 `deferredEvents`；最后在锁外 `deferred.callback(deferred.targetObject)`。

**状态机要点**：`mActiveOverlaps[handle]` 即"上一帧重叠集"；`currentOverlaps` 为"本帧重叠集"。`Enter = 本帧有 && 上帧无`，`Stay = 本帧有`（每帧无条件发），`Exit = 上帧有 && 本帧无`。`nearbyObjects` 在循环间复用（`GridSearch::Get` 内部应会 clear；移植时需确认 3D 版同样重置）。

**两处真实缺陷（移植前应决定是否保留语义）**：
1. `TriggerConfig::TriggerLayers` **被完整读写但 `ProcessTriggers` 从未使用**——触发事件不做任何层级过滤。
2. 重叠检测是**点包含** `TriggerBounds.Contains(obj->PFGetPos())`，而非形状 vs AABB。3D 化时若沿用点测试，大物体"擦边"不会触发。

### 3.4 2D 相关点与 3D 改动

- `Vec2_ minPos/maxPos` → `Vec3_`；`GridSearch::Get(Vec2_ Spos, Vec2_ Epos, std::vector<PhysicsFormwork*>&)`（`GridSearch.hpp:630`）→ 3D 版 `Get(Vec3_, Vec3_, ...)`，`GridSearch` 的 Morton/Z-order 编码（`GridSearch.hpp:595-724` 一带）需换成 3D Morton 码与 z 分量遍历。
- `Bounds`（`PhysicsBlockTypes.hpp:71-122`）→ `Bounds3`：`Vec3_ Center/HalfSize`；`Contains` 加 `(point.z >= Center.z-HalfSize.z) && (point.z <= Center.z+HalfSize.z)`；`Overlaps` 加一条 z 轴分离判断（六向分离）。
- 液体粒子跳过、延迟回调、锁范围、句柄管理**全部维度无关**。
- 建议：3D 版把"点包含"升级为"物体 3D AABB / 包围球 vs 触发盒"，并真正应用 `TriggerLayers`。

## 6. `MovementUtil.hpp`（76 行）

### 6.1 定位
"方案E混合驱动"配套工具：把上层 `MovementComponent` 的抽象意图（目标速度/朝向）换算成物理引擎可接受的力或插值系数，走 `AddForce → 牛顿积分` 路径，从而自动尊重 `mass` / kinematic 状态（文件头注释 :8-12）。

### 6.2 逐函数

**（1）`inline Vec2_ ComputeMoveForce(const Vec2_& currentSpeed, const Vec2_& desiredSpeed, FLOAT_ mass, FLOAT_ dt)`（:28-43）**
```cpp
if (mass <= 0 || dt <= 0) { return {0, 0}; }
#if Define_MinSpoilageBool
const FLOAT_ damp = Define_MinSpoilage;
#else
const FLOAT_ damp = FLOAT_(1);
#endif
const FLOAT_ invDt = FLOAT_(1) / dt;
return Vec2_{ (desiredSpeed.x - damp * currentSpeed.x) * mass * invDt,
              (desiredSpeed.y - damp * currentSpeed.y) * mass * invDt };
```
推导（注释 :22-27）：由 `PhysicsParticle::PhysicsSpeed` 的 `speed_next = damp * speed_cur + dt * (Ga + invMass * force)`，忽略重力（Ga 由 `PhysicsWorld` 统一施加），令 `speed_next = desiredSpeed`，得 `force = mass * (desiredSpeed - damp*currentSpeed) / dt`。`damp = Define_MinSpoilage`（开阻尼时 0.9994，否则 1.0）。用途：让物体数帧内平滑趋近目标速度且稳态误差为 0。

**（2）`inline float SmoothK(float rate, float dt)`（:53-56）**
```cpp
return 1.0f - std::exp(-rate * dt);
```
帧率无关指数平滑系数 `k = 1 - exp(-rate*dt)`，用法 `value = lerp(value, target, k)`；用于朝向平滑跟随、Ragdoll 模式恢复等。

**（3）`inline float LerpAngle(float current, float target, float k)`（:67-74）**
```cpp
constexpr float TWO_PI = 6.28318530717958647692f;
constexpr float PI = 3.14159265358979323846f;
float diff = std::fmod(target - current + PI * 3.0f, TWO_PI) - PI;
if (diff < -PI) diff += TWO_PI;
return current + diff * k;
```
把角差规整到 `(-π, π]`，保证走最短弧（不会出现"转 350° 到 +10°"）。用于消除角色朝向瞬切。

### 6.3 2D 专用部分与 3D 改动
- `ComputeMoveForce` 是**逐分量 Vec2_ 运算** → 3D 直接换成 `Vec3_`，公式（含 `mass<=0 || dt<=0` 早退、`damp` 分支）不变。
- `LerpAngle` 是**标量角最短弧插值** → 3D 朝向应改用**四元数 slerp**（`glm::slerp`）取代；若角色朝向仍以欧拉角表示，则每轴各自调用 `LerpAngle`（注意万向节与轴序）。
- `SmoothK` 与维度无关，保留。

## 8. `PhysicsAuxiliaryVision.hpp`（158 行）+ `.cpp`（544 行）

### 8.1 目的与算法性质

**目的**：把物理世界以线框/点的方式**绘制到 `VulKan::AuxiliaryVision`**（Vulkan 辅助视觉叠加层），供调试观察。头文件用前向声明 `namespace VulKan { class AuxiliaryVision; }`（hpp:6-9）避免把 Vulkan 头链引入，完整定义只在 .cpp 中 include（.cpp:6 `#include "../VulkanTool/AuxiliaryVision.h"`）。

**算法性质（明确回答任务中的疑问）**：**本文件不做 raycasting，也不计算 visibility polygon / 光照遮挡**。它是纯粹的**调试线框渲染 + 外轮廓去重**。唯一算得上"算法"的是 `DrawCellOutline` 的**相邻格子共享边去重**：相邻两个实体格子的公共边本会被画两次，改为"仅当邻格非实体（或越界）时才画该边"，线段数接近减半（.cpp:17-27 注释）。

### 8.3 内部辅助 `DrawCellOutline`（.cpp:32-57，匿名命名空间）

```cpp
template <typename IsEntityFn>
void DrawCellOutline(VulKan::AuxiliaryVision *av, int gx, int gy,
                     glm::dvec2 origin, FLOAT_ angle, glm::vec2 centreMass,
                     glm::vec4 color, bool isStatic, IsEntityFn IsEntity)
{
    glm::dvec2 A = origin + glm::dvec2(vec2angle(Vec2_{(FLOAT_)gx, (FLOAT_)gy} - centreMass, angle));
    glm::dvec2 B = origin + glm::dvec2(vec2angle(Vec2_{(FLOAT_)(gx+1), (FLOAT_)gy} - centreMass, angle));
    glm::dvec2 C = origin + glm::dvec2(vec2angle(Vec2_{(FLOAT_)gx, (FLOAT_)(gy+1)} - centreMass, angle));
    glm::dvec2 D = origin + glm::dvec2(vec2angle(Vec2_{(FLOAT_)(gx+1), (FLOAT_)(gy+1)} - centreMass, angle));

    if (!IsEntity(gx, gy-1)) (isStatic ? av->AddStaticLine({A,0},{B,0},color) : av->Line({A,0},color,{B,0},color));
    if (!IsEntity(gx, gy+1)) (isStatic ? av->AddStaticLine({C,0},{D,0},color) : av->Line({C,0},color,{D,0},color));
    if (!IsEntity(gx-1, gy)) (isStatic ? av->AddStaticLine({A,0},{C,0},color) : av->Line({A,0},color,{C,0},color));
    if (!IsEntity(gx+1, gy)) (isStatic ? av->AddStaticLine({B,0},{D,0},color) : av->Line({B,0},color,{D,0},color));
}
```
四角世界坐标 = `origin + rotate({gx,gy} - centreMass, angle)`；`angle=0` 时退化为轴对齐。

## 9. 跨文件转换优先级建议（基于本批 8 文件的证据）

1. **先做类型底座**：`Vec2_→Vec3_`、`Bounds→Bounds3`、`angle→quat`、`angleSpeed→vec3`、`invMomentInertia→mat3`、`glm::ivec2→ivec3`。本批文件中 `Bounds`（`PhysicsBlockTypes.hpp:71-122`）与 `PhysicsJunction` 的全部数学是最硬的两块。
2. **`PhysicsJunction` 是唯一需要重写数学的仿真文件**（4.2–4.6 的表格逐条对应），其余三个仿真文件（Collision/Kinematic/Trigger）都是"容器与状态机 + 少量向量运算"。
3. **`PhysicsAssembly` 与回调/层级/优先级/句柄体系零改动**，可先原样编译通过。
4. **两个调试文件（ImGuiPhysics / PhysicsAuxiliaryVision）可最后处理或整体剥离**；它们对仿真无反向依赖（`PhysicsAuxiliaryVision` 依赖 `ImGuiPhysics` 的开关宏与 `AuxiliaryVision`，`PhysicsDebugView::drawUI` 依赖 ImGui）。
5. **移植时顺带修复的既有缺陷**（不改语义、仅修 bug）：
   - `PhysicsCollision.cpp:204-206` B 侧 OnEnter 误用 `Ait->first`；
   - `PhysicsJunction` 各 `PreStep` 缺 `L ≈ 0` 保护（两端重合产生 NaN）；
   - `PhysicsTrigger` 的 `TriggerLayers` 从未生效、且只用点包含检测；
   - `PhysicsKinematic::RotateTo/UpdateKinematicMotion` 用线性角插值而非最短弧（3D 换 slerp 时自然解决）；
   - `BaseJunction::P` 累积冲量声明未用（3D 若要稳定求解应启用累积+钳制）。
